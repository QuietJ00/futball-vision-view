# Hybrid Pitch Calibration 검증 보고서

실행일 2026-11-04. 환경: Apple M4 Pro, CPU 12코어, Python 3.12, OpenCV 5.0. 합성 실험은 씨드 42~46, 61개 장면, 총 2,440회. 원본 수치는 `comparison.csv`, `summary.json`, `real.json`에서 확인할 수 있다.

## 1. 결론

**운영 기본값 유지를 권고한다.** 실측 위치·속도 정답이 없으며, 합성 실험에서 앞선 방식이 실제 영상에서도 우세하다는 근거를 얻지 못했다.

- 합성에서는 라인 이름이 주어지면 D/E가 A보다 정확했다. AUTO의 위치 오차 중앙값은 A 대비 오라클에서 97%, 노이즈에서 86% 감소했다.
- 라인 이름을 제공하는 공개 AI 모델은 아마추어 영상에서 동작하지 않았다. 실제 키프레임 37장에서 검출한 라인은 0개였다.
- 먼 터치라인을 입력에 넣기 전까지 실제 영상에서 D/E의 오차가 컸다(13:09 D 골라인 136 m, 09:20 E 39 km/h). 입력을 고친 뒤 D는 S와 비슷해졌고, E는 여전히 가장 불안정했다.
- 검토할 만한 후보는 AI 없이 동작하는 기하 솔버 S와 S가 붙인 라인 이름을 받는 D다. 스탠드 높이 클립 3개를 수동 입력 없이 보정했고, 낮은 카메라 7구간은 모두 거부했다. 수동 보정보다 정확하다는 근거는 얻지 못했다.

일반 영상에서 AI가 라인을 이해해 정확한 좌표를 내는 최종 목표는 **달성하지 못했다.**

## 2. 구현 범위

| 구분 | 내용 |
|---|---|
| `autohl/hybrid_calib.py` | 이름 붙은 라인 입력의 C/D/E, 렌즈 왜곡, 모델 불일치 시 복귀(AUTO). `tripod_calib.py`로 계획한 기능은 비교를 위해 이 파일에 통합했다 |
| `autohl/field_solver.py` | 라벨 없는 페인트, 사람 키, 카메라 움직임으로 카메라를 찾는 솔버 S. `AUTOHL_CALIBRATOR=camera`일 때만 동작 |
| `autohl/semantic_pitch.py` | HRNetV2-W48 독립 구현과 라인 클래스 정의, 출력 구조. PnLCalib 가중치(CC BY 4.0)를 `weights_only`로 읽음 |
| `experiments/hybrid_pitch/` | 합성 데이터, A~E 어댑터, 벤치마크, 실제 영상 평가, 보고서 생성 |
| 기존 코드 수정 | 호모그래피 보간 부호 버그 수정(`pitch.blend`), 기능 플래그 추가 |

### 약점

- **렌즈 왜곡(k1 −0.1, −0.2)**: C 0%, D/E/AUTO 20% 성공. 성공한 클립에서도 오차가 60 m 이상이었다. 이 조건에서는 A(2.2 m), B(1.0 m)의 오차가 더 작았다. 실제 클립에서 추정한 k1은 약 −0.07이었다.
- **카메라 이동**: D 0.52 m, E 0.70 m로 C(0.03 m)보다 오차가 컸다. AUTO는 다른 방식으로 전환해 0.17 m를 기록했다.
- **선이 적은 장면**: A, B, C 모두 0%. D/E의 보정 성공률은 100%였고 오차는 0.3~0.4 m였다.
- **먼 구석의 오차**: `position_heatmap.png`에서 AUTO의 먼 구석 평균 오차는 10 m 이상으로 A보다 컸다.
- 실패 클립은 위치 표에서 빠지므로 성공률과 함께 해석해야 한다.

## 7. 수정한 기존 버그

`field_geometry._project_map`의 호모그래피 보간은 팬이 경기장 원점을 지나면 부호가 뒤집혀 서로 상쇄될 수 있었다. 합성 실험에서 C의 거리 오차가 10^15 m까지 나와 `pitch.blend`로 수정했다. 이 수정이 기존 실제 영상 결과에 미친 영향은 별도로 측정하지 않았다.

## 8. 선 안정화와 먼 터치라인 수정

비교 영상에서 발견한 두 문제를 수정했다. 측정 환경은 위 실제 클립과 같다.

- **선이 잔디 위를 미끄러짐**: 약 1초 간격의 기준 프레임을 따로 보정해 서로 최대 80 px 어긋났다. 구장선이 충분히 보이는 기준만 남기고 기준 간 차이를 구간 전체에 분산해 보정한다.
- **단일 기준 프레임에 고정하는 방식은 채택하지 않았다.** 미끄러짐은 0 px였지만 145프레임 뒤 약 70 px 어긋났다.
- **먼 터치라인이 트랙 위에 그려짐**: 잔디 끝의 선이 페인트 검출에서 빠져 있었다. 빨간 트랙과 잔디의 경계를 먼 터치라인으로 사용한다. 트랙이 없는 구장에서는 이 단서를 사용할 수 없다.
- **폭 60 m 재확인**: 폭 57, 60, 63 m를 스캔했지만 데이터만으로 확정할 수 없어 실측값 60 m를 유지했다.

## 9. 도입 권고

1. **기본값은 A를 유지한다.** 수동 기준점과 기존 자동 경로를 그대로 둔다.
2. **S는 기능 플래그로만 활성화한다.** 스탠드 높이 영상에서 사람이 오버레이를 확인하는 초안으로 쓰기에 적합하다.
3. **D/E와 AI 라인 경로는 도입하지 않는다.** 실제 영상에서 실패가 관측됐다.
4. **도입 전 필요한 것**
   - 선수 GPS 또는 줄자로 잰 왕복 기준 주행 2~3회: 실제 km/h와 미터를 처음으로 검증
   - 다른 구장 영상
   - 아마추어 영상 라벨 데이터: S로 푼 스탠드 클립의 투영 결과를 초기 라벨로 쓰고 사람이 교정해 미세조정 시도. 학습·평가는 촬영 세션 단위로 분리
