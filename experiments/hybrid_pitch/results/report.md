# Hybrid Pitch Calibration 검증 보고서

실행일 2026-11-04. 환경: Apple M4 Pro, CPU 12코어, Python 3.12, OpenCV 5.0. 합성 실험은 씨드 42~46, 61개 장면, 총 2,440회. 수치 원본은 `comparison.csv`, `summary.json`, `real.json`이에요.

## 1. 결론

**운영 기본값은 바꾸지 않는 것을 권고해요 (Scenario 5, 일부 Scenario 4).** 실측 위치·속도 정답이 없고, 합성 실험의 우위가 실제 영상으로 옮겨 가지 않았어요.

- 합성에서는 라인 이름이 주어지면 D/E가 A보다 훨씬 정확해요. AUTO는 A 대비 위치 오차 중앙값이 오라클 97%, 노이즈 86% 감소했어요.
- 그 라인 이름을 줄 AI가 아마추어 영상에서는 동작하지 않아요. 공개 모델이 실제 키프레임 37장에서 라인을 0개 검출했어요.
- 자동 이름표를 붙인 실제 영상의 D/E는 무너졌어요. 13:09 클립 D는 골라인 오차가 136 m, 09:20 클립 E는 질주 속도가 39 km/h였어요.
- 쓸 만한 후보는 AI가 없는 기하 솔버 S예요. 스탠드 높이 클립 3개를 사람 입력 없이 풀고, 낮은 카메라 7구간은 전부 거부했어요. 단 손 보정보다 정확하다고 입증하지는 못했어요.

일반 영상에서 AI가 라인을 이해해 정확한 좌표를 내는 최종 목표는 **달성하지 못했어요.**

## 2. 구현 범위

| 구분 | 내용 |
|---|---|
| `autohl/hybrid_calib.py` | 이름 붙은 라인 입력의 C/D/E, 렌즈 왜곡, 모델 불일치 시 복귀(AUTO). 요청서의 `tripod_calib.py`는 비교를 위해 이 파일에 합쳤어요 |
| `autohl/field_solver.py` | 라벨 없는 페인트, 사람 키, 카메라 움직임으로 카메라를 찾는 솔버 S. `AUTOHL_CALIBRATOR=camera`일 때만 동작 |
| `autohl/semantic_pitch.py` | HRNetV2-W48 독립 구현과 라인 클래스 정의, 출력 구조. PnLCalib 가중치(CC BY 4.0)를 `weights_only`로 읽음 |

### 약점

- **렌즈 왜곡(k1 −0.1, −0.2)**: C 0%, D/E/AUTO 20% 성공. 성공 클립도 60 m 이상 오차예요. 이 조건에서는 A(2.2 m), B(1.0 m)가 나아요. 실제 클립에서 추정한 k1은 약 −0.07이었어요.
- **카메라 이동**: D 0.52 m, E 0.70 m로 C(0.03 m)보다 나빠요. AUTO는 복귀해서 0.17 m였어요.
- **선이 적은 장면**: A, B, C 모두 0%. D/E는 100% 풀지만 0.3~0.4 m예요.
- **중앙값이 가리는 꼬리**: `position_heatmap.png`에서 AUTO의 먼 구석 평균 오차는 10 m 이상으로 A보다 나빠요.
- 실패 클립은 위치 표에서 빠지므로 성공률과 함께 봐야 해요.

## 7. 수정한 기존 버그

`field_geometry._project_map`의 호모그래피 보간은 팬이 경기장 원점을 지나면 부호가 뒤집혀 서로 상쇄될 수 있었어요. 합성에서 C의 거리 오차가 10^15 m까지 나오는 것으로 드러났고, `pitch.blend`로 수정했어요. 이 수정이 기존 실제 결과를 얼마나 바꾸는지는 따로 재지 않았어요.

## 8. 도입 권고

1. **기본값은 A를 유지해요.** 수동 기준점과 기존 자동 경로를 그대로 둬요.
2. **S는 플래그로만 열어요.** 스탠드 높이 영상에서 사람이 오버레이를 확인하는 초안으로 쓰기에 적합해요.
3. **D/E, AI 라인 경로는 도입하지 않아요.** 실제 영상에서 실패가 측정됐어요.
4. **도입 전 필요한 것**
   - 선수 GPS 또는 줄자로 잰 왕복 기준 주행 2~3회: 실제 km/h와 미터를 처음으로 검증
   - 다른 구장 영상
   - 아마추어 영상 라벨 데이터: S로 푼 스탠드 클립의 투영 결과를 초기 라벨로 쓰고 사람이 교정해 미세조정 시도. 학습·평가는 촬영 세션 단위로 분리
